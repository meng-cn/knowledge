# Vibe vs Spec 对比分析

> **在知识图谱中的位置**：模块四 · 04_vibe_vs_spec · 第 1 节
> **难度**：⭐⭐⭐

---

## 1. 核心对比

### 工作模式对比

| 维度 | Vibe Coding | Spec-Driven Development |
|--|-|--|
| **交互方式** | 对话式（"Make it bigger"） | 文档式（详细 PRD） |
| **开发速度** | 极快（秒级反馈） | 中等（需写 PRD） |
| **代码质量** | 不可预测 | 可预测、可验证 |
| **适用阶段** | 创意探索、快速原型 | 生产开发、团队协作 |
| **可维护性** | 低（代码结构混乱） | 高（按规格执行） |
| **团队协作** | 困难（无规格文档） | 容易（PRD 对齐） |
| **可追溯性** | 低（对话历史不结构化） | 高（需求→代码映射） |
| **学习曲线** | 低（谁都会写 Prompt） | 中（需学会写 PRD） |
| **成本** | 低（工具免费） | 中（需花时间写 PRD） |
| **适合人群** | 初学者、独立开发者 | 团队、专业开发者 |

### 核心范式对比

```
Vibe Coding:
  用户意图 → 对话 → AI 理解意图 → 生成代码
  (模糊 → 调整 → 模糊)

Spec Coding:
  详细需求 → PRD → AI 执行 PRD → 生成代码
  (具体 → 执行 → 验证)
```

---

## 2. Vibe Coding 的优缺点

### ✅ 优点

- 极速原型（几分钟出可用版本）
- 低门槛（不需要深厚的编程知识）
- 创意自由（探索式设计空间大）
- 学习曲线低

### ❌ 缺点

- 代码质量不可控
- 无架构规划
- 不适合团队协作
- 代码难以维护
- 缺乏安全保证

---

## 3. Spec Coding 的优缺点

### ✅ 优点

- 代码质量可预测
- 可测试、可验证
- 团队协作友好（PRD 作为对齐工具）
- 代码结构清晰
- 生产就绪

### ❌ 缺点

- 写 PRD 需要时间
- 灵活性较低
- 学习曲线较陡
- 过度规格可能导致僵化

---

## 4. 典型场景对比

| 场景 | Vibe Coding | Spec Coding | 推荐 |
|--|-|-|--|
| 个人 Todo App 原型 | ✅ 极快 | ⚠️ 有点大材小用 | Vibe |
| SaaS MVP | ✅ 快速验证想法 | ⚠️ PRD 耗时 | Vibe (原型) |
| 企业 ERP 系统 | ❌ 代码不可控 | ✅ 生产就绪 | Spec |
| 团队协作项目 | ❌ 无规格文档 | ✅ PRD 对齐 | Spec |
| 创意 UI 探索 | ✅ 探索空间大 | ⚠️ 过于结构化 | Vibe |
| 代码库重构 | ❌ 缺乏规划 | ✅ 按规格执行 | Spec |
| 学习新技术 | ✅ 快速试错 | ⚠️ 过于正式 | Vibe |
| 安全敏感系统 | ❌ 无法审计 | ✅ 可审计 | Spec |
