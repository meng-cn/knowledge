# Vibe vs Spec 选型指南

> **在知识图谱中的位置**：模块四 · 04_vibe_vs_spec · 第 2 节
> **难度**：⭐⭐⭐

---

## 1. 选型决策树

```
选择编程范式：
  ├── 项目处于什么阶段？
  │   ├── 创意探索 → Vibe Coding
  │   ├── 需求定义 → Spec Coding (PRD)
  │   ├── 原型开发 → Vibe Coding
  │   ├── 功能开发 → Spec Coding
  │   └── 生产发布 → Spec Coding (完整 Spec)
  │
  ├── 项目复杂度？
  │   ├── 简单 (1-2 页) → Vibe Coding
  │   ├── 中等 (3-5 页) → Vibe + 轻量 Spec
  │   └── 复杂 (>5 页) → Spec Coding
  │
  ├── 团队规模？
  │   ├── 个人 → Vibe 为主 + 关键模块 Spec
  │   ├── 小团队 (2-5) → Vibe + Spec 混合
  │   └── 大团队 (>5) → Spec Coding 为主
  │
  └── 安全/合规要求？
      ├── 无 → Vibe Coding
      ├── 中等 → Spec Coding
      └── 高 (金融/医疗) → Spec Coding + 安全审计
```

---

## 2. 推荐组合

### 组合一：个人开发者（快速验证）

| 阶段 | 范式 | 工具 |
|--|-|-|
| 创意探索 | Vibe Coding | Cursor Composer / ChatGPT |
| 原型开发 | Vibe Coding | Cursor / Claude Code |
| 验证需求 | Vibe Coding | ChatGPT |
| MVP 开发 | 混合模式 | Cursor + 轻量 PRD |

### 组合二：小团队（平衡速度与质量）

| 阶段 | 范式 | 工具 |
|--|-|-|
| 创意探索 | Vibe Coding | Cursor / Claude Code |
| 需求定义 | Spec Coding | PRD + BDD |
| 功能开发 | Spec Coding | Cursor Composer + PRD |
| 代码审查 | 混合 | AI Code Review + 人工审查 |

### 组合三：企业团队（质量优先）

| 阶段 | 范式 | 工具 |
|--|-|-|
| 需求分析 | Spec Coding | AI-Optimized PRD + BDD |
| 架构设计 | Spec Coding | PRD + 架构文档 |
| 功能开发 | Spec Coding | Cursor/Claude Code + PRD |
| 测试 | Spec Coding | AI-Generated Tests + 人工 |
| 代码审查 | 混合 | AI Review + 人工 Review |

---

## 3. 何时该用 Vibe Coding

- ✅ 创意探索阶段
- ✅ 快速原型 / POC
- ✅ 个人 Side Project
- ✅ 学习新技术
- ✅ UI/UX 设计迭代

## 4. 何时该用 Spec Coding

- ✅ 生产代码
- ✅ 团队协作
- ✅ 复杂业务系统
- ✅ 长期维护项目
- ✅ 安全敏感系统
- ✅ 合规要求行业

---

## 5. 混合模式：Vibe + Spec 最佳实践

**推荐模式**：Vibe 探索 + Spec 落地

```
Step 1: Vibe Coding 探索想法（快速迭代 3-5 轮）
Step 2: 将探索结果整理成 PRD（Spec）
Step 3: 用 Spec 驱动 AI 生成生产代码
Step 4: 人工审查 + 测试
```
