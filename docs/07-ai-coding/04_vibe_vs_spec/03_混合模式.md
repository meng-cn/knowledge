# 混合模式：Vibe + Spec

> **在知识图谱中的位置**：模块四 · 04_vibe_vs_spec · 第 3 节
> **难度**：⭐⭐

---

## 1. 混合模式核心理念

Vibe Coding 和 Spec-Driven Development 不是非此即彼的对立关系，而是互补关系：

```
Vibe Coding (灵活) + Spec Coding (规范) = 最佳实践

探索阶段: Vibe → 快速试错、创意发散
落地阶段: Spec → 规范落地、质量保证
```

---

## 2. 推荐工作流

```
┌────────────────────────────────────────────┐
│   Vibe + Spec 混合工作流                    │
│                                            │
│  1. Vibe Coding 探索 (3-5 轮对话)         │
│     ↓ 确定最终方案                           │
│  2. 整理 PRD (Spec)                         │
│     ↓ PRD 包含技术栈/API/Schema              │
│  3. AI Agent 按 PRD 生成代码                 │
│     ↓ AI 生成代码                            │
│  4. 人工审查 + 测试                         │
│     ↓ 测试通过                               │
│  5. 提交 PR / 部署                           │
└────────────────────────────────────────────┘
```

---

## 3. 实践示例

### 阶段一：Vibe 探索

```
开发者: "I want a dashboard with auth, a database, and charts"
AI: [生成一个基础版本]
开发者: "Make it blue, add a sidebar"
AI: [修改]
开发者: "Add user management"
AI: [添加]
...
```

### 阶段二：整理 PRD

```markdown
# Dashboard App PRD
## 技术栈
- React + TypeScript + Tailwind CSS
- PostgreSQL
- JWT Auth

## 功能
1. 用户认证 (邮箱/密码 + OAuth)
2. 数据报表 (Chart.js)
3. 用户管理 (CRUD)

## API
...

## Schema
...
```

### 阶段三：AI 按 PRD 生成生产代码

```
开发者: "按照以下 PRD 生成完整代码 [粘贴 PRD]"
AI: [按 PRD 生成完整代码 + 测试]
```
